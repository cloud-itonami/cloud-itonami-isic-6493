開示: 現金移動経路で承認者の帰属が失われている

未修正 上表のうち 9 件 のレジスタ書き込みで、承認した人間の id がコミット後の状態から復元できない。内訳: receivable/underwrite → receivables / solvency/attest → attestations / advance/fund → receivables / advance/fund → advances / receivable/collect → receivables / reserve/settle → receivables / reserve/settle → settlements。

原因は factoring.operation/commit-record が承認者を :payload にのみ載せる (:value には載せない) 一方、factoring.store の commit-record! が effect ごとに異なる経路を通ることにある: :verification/set と :underwriting/set は :payload をそのまま格納するため承認者が残るが、:advance/mark-funded と :settlement/mark-settled は payload を使わず advance!/settle! が組み立てたレコードを追記するため、承認者はどこにも書かれない。

これは書類経路ではなく現金経路で起きている。 この actor が実世界で行う金銭移動は 2 つ (:advance/fund = クライアントへの現金前渡し、:reserve/settle = 留保金の解放) で、その 2 つがちょうど、どの人間が承認したかを SSoT から復元できない操作である。両者は factoring.phase のどの phase でも auto-commit されず、必ず人間の承認を要求する設計であるにもかかわらず、その承認の記録が残らない。

本タスクはレンダラの追加であり、この欠陥は修正せず開示する (store の commit 経路の変更は本タスクの範囲外)。

警告: ledger の :actor は承認者ではない

監査 ledger の :committed ファクト 14 件が持つ :actor の値は `op-1` のみで、これは factoring.operation/commit-fact が (:actor-id context) から埋める実行アクターであって承認者ではない。本ページはすべての承認者 id を実行アクター id (op-1) と異なる値にしているため、この 2 つが偶然一致して :actor を承認記録と誤読する余地が無い — 実測: 承認者 id が :actor に現れたか = いいえ。
